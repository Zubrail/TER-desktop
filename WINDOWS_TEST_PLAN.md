# TER для Windows — что проверить (по опыту Mac, 13.10.2026)

Тест-стенд: Windows 11 ARM в UTM на Mac владельца (x64-сборка идёт через эмуляцию Windows; позже — сборка win-arm64).
Сборка: `package-ter-win.sh` → `dist/TER-<ver>-win-x64.zip`. Ядра из официальных релизов, суммы сверены (`cores/win`).
Доступ: OpenSSH Server в Windows. GUI из SSH не видно (сессия 0) — тур запускать задачей планировщика
в сессии пользователя (`schtasks /create ... /it`), снимки `ter-shot-*.png` забирать по scp.

| # | Что | Почему (что было на Mac / чем отличается Windows) | Как проверяем |
|---|-----|------|------|
| 1 | Весь трафик (TUN) | Mac: пароль sudo, 0.6.1 висел, т.к. окно upstream не регистрировалось. Windows: нужны права администратора (upstream делает RebootAsAdmin). Наш EnsureTunAsync на не-Mac выходит сразу | сделать своё окно «Перезапустить TER с правами администратора» или запуск всегда «от администратора» (manifest), проверить wintun, сайт, Telegram |
| 2 | Трей (**сделано в 0.6.5**, проверить) | TermitusTray — нативный NSStatusItem/NSMenu macOS | левый клик = окно поднимается (и из свёрнутого), правый = меню TER (Подключить, Страна ›, Открыть TER, Сообщить о проблеме, «Для опытных ›», Выход); значок серый → мятный при подключении → янтарный при «подключаемся»; подсказка «TER — подключено/отключено»; после смены страны/подключения меню показывает новое состояние |
| 3 | Обновление (**сделано в 0.6.5**, проверить) | Mac заменяет .app; Windows не даёт заменить запущенный .exe | `python3 termitus/tools/make_update_fixture.py` + фейковый сервер с zip `TER/…`; TER в папке с правом записи (не Program Files): «Обновить» → окно закрылось → через несколько секунд запустилась новая версия (проверить номер в «О программе»), рядом нет `TER.old-*` после следующего запуска, в `%LOCALAPPDATA%\TeRMiTuS\update` пусто. Проверить: папка с кириллицей и пробелом; TER в `C:\Program Files` → честное сообщение и показ архива; испорченный zip (sha не совпал) → не ставится; ядро/TUN не остались висеть (`tasklist`, wintun-адаптера нет); откат: заблокировать файл в папке TER (открыть dll/exe в другом процессе) → через ~10 с старая версия снова запущена, `%LOCALAPPDATA%\TeRMiTuS\update-result.txt` на следующем старте попадает в журнал как «result = RolledBack/RenameFailed» |
| 4 | «Включён другой VPN» (**сделано в 0.6.5**, проверить) | парсит `netstat -rn` macOS | включить любой другой VPN (WireGuard/OpenVPN/Tailscale с exit node) и нажать «Подключить» → окно «включён другой VPN»; выключить → подключается; свой TUN TER (singbox_tun/xray_tun) предупреждения не вызывает (подключиться, отключиться, снова подключиться); Hyper-V/VirtualBox/Teredo не считаются VPN |

| 6 | Права на файлы | Mac 0700/0600 (Unix) | на Windows этот код пропускается; данные в %APPDATA%, не рядом с exe (NotStoreConfigHere) |
